# MQTT 服务调用类关系说明

本文说明当前 IoT 服务中 HTTP 调用、MQTT 发布、MQTT 响应分发和 pending 完成的职责边界。

## 类依赖图

```mermaid
flowchart LR
    controller["ServiceInvokeController<br/>HTTP 调用入口"]
    invokeService["ServiceInvokeService<br/>调用编排和 HTTP 映射"]
    routeResolver["DeviceRouteResolver<br/>解析设备接入路由"]
    registry["PendingRequestRegistry<br/>管理待完成请求"]
    gateway["HiveMqttGateway<br/>发布 MQTT 消息"]

    lifecycle["HiveMqttClientLifecycle<br/>连接、订阅和断开"]
    subscriber["HiveMqttUpstreamSubscriber<br/>订阅服务响应 Topic"]
    dispatcher["MqttUpstreamDispatcher<br/>解析 Topic 和 payload"]
    responseHandler["ServiceResponseHandler<br/>校验身份并完成 pending"]
    mqttClient["Mqtt5AsyncClient<br/>HiveMQ 异步客户端"]
    emqx["EMQX<br/>MQTT Broker"]

    controller --> invokeService
    invokeService --> routeResolver
    invokeService --> registry
    invokeService --> gateway
    gateway --> mqttClient
    lifecycle --> mqttClient
    lifecycle --> subscriber
    subscriber --> mqttClient
    subscriber --> dispatcher
    dispatcher --> responseHandler
    responseHandler --> registry
    mqttClient <--> emqx
```

## 调用时序图

```mermaid
sequenceDiagram
    participant Frontend as 前端
    participant Service as ServiceInvokeService
    participant Registry as PendingRequestRegistry
    participant Gateway as HiveMqttGateway
    participant EMQX as EMQX
    participant Device as 设备或网关
    participant Subscriber as HiveMqttUpstreamSubscriber
    participant Dispatcher as MqttUpstreamDispatcher
    participant Handler as ServiceResponseHandler

    Frontend->>Service: POST /service/invoke
    Service->>Service: 解析路由并生成字符串 msgId
    Service->>Registry: register(msgId, identity, timeout)
    Service->>Gateway: publish(MqttPublishRequest)
    Gateway->>EMQX: publish down/.../request
    EMQX->>Device: 下发服务调用
    Device->>EMQX: publish up/.../response
    EMQX->>Subscriber: 推送服务响应
    Subscriber->>Dispatcher: dispatch(topic, payload)
    Dispatcher->>Handler: handle(metadata, message)
    Handler->>Registry: complete(msgId, ServiceResponseMessage)
    Registry-->>Service: CompletableFuture 完成
    Service-->>Frontend: Result.success 或 Result.fail
```

## 职责说明

- `ServiceInvokeService` 负责路由、消息构造、pending 注册、MQTT 发布和 HTTP 结果映射，不处理 MQTT 订阅。
- `PendingRequestRegistry` 是唯一 pending 状态持有者，负责注册、完成、失败、取消、超时和容量限制。
- `HiveMqttGateway` 只发布 `MqttPublishRequest`，不解析响应或完成 HTTP 请求。
- `HiveMqttUpstreamSubscriber` 只订阅直连设备和网关子设备的服务响应过滤器，并把原始 Topic、payload 交给分发器。
- `MqttUpstreamDispatcher` 严格解析 Topic，校验响应字段类型，并构造 `ServiceResponseMessage`。
- `ServiceResponseHandler` 对比 Topic、网关 target 与 pending 预期身份；合法响应无论成功或失败都以完整消息完成 pending。
- `HiveMqttClientLifecycle` 负责应用启动连接、订阅响应 Topic 和关闭连接。

当前不提供 mock MQTT HTTP 接口。真实 MQTT 回调和端到端测试使用同一条响应处理链。
